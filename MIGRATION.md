# Перенос HVF с GitHub Pages

Новый адрес: https://hvf-app.haveffee-assistant.workers.dev/ . Cloudflare уже обслуживает приложение; приём платежей выключен. GitHub используется для исходников и проверок, а не для основного SaaS-хостинга.

## Что сохранить

1. На старом устройстве дождаться «Всё синхронизировано» и скачать полную JSON-копию из настроек. Экспорт содержит личные данные; не класть его в репозиторий или публичный сайт.
2. Новый адрес использует тот же Firebase-проект **daily-schedule-sync-fc374**. Похожий **daily-schedule-sync-f4ba5** — другой проект, его настройки не влияют на нынешние записи.
3. В консоли владельца fc374 открыть Authentication → Settings → Authorized domains и добавить `hvf-app.haveffee-assistant.workers.dev` без схемы и пути. Во французском интерфейсе: Authentication → Paramètres → Domaines autorisés → Ajouter un domaine.
4. На новом адресе войти в тот же Google-аккаунт и проверить свои дела, цели и финансы. Локальные анонимные записи при необходимости восстановить из файла; мастер восстановления сначала показывает предварительный результат.
5. На iPhone добавить новый адрес из Safari на главный экран. Разрешение и подписка Web Push другого адреса не переносятся: включить напоминания заново и получить тестовое уведомление.
6. После проверки нового уведомления отключить старые напоминания на прежнем устройстве, иначе оба адреса могут отправлять одно событие. На странице переезда предусмотрена отдельная кнопка, отключающая только текущую подписку старого адреса.

## Переключение старого адреса

До проверки нового входа старая рабочая версия должна оставаться доступной. После проверки запустить GitHub Actions → **Publish legacy GitHub Pages migration** → Run workflow. Это заменит старый сайт страницей перехода, входа для синхронизации и экспорта; приложение не будет автоматически открывать другой адрес и не очистит localStorage.

Новый legacy service worker не перехватывает запросы, не очищает локальные записи и не принуждает активную вкладку к перезагрузке. Старые push-клики открывают новый адрес с корректной датой. Старые уведомления выключаются только явным действием пользователя.

## Размещение и платежи

Cloudflare подходит для работающей бесплатной беты. Для реальных продаж через bePaid нужно согласовать продавца и инфраструктуру: текущие требования провайдера включают собственный домен, размещение сервера в Беларуси, регистрацию ресурса и отсутствие бесплатного хостинга. Не включать оплату на текущем адресе до подтверждения провайдера. Сборка статического приложения переносима; серверные адаптеры и Firebase интеграцию нужно проверить на согласованном размещении.

Тарифы утверждены: 8 BYN/месяц, 72 BYN/год. По умолчанию платёжный Worker возвращает `paymentsReady:false`, и ни checkout, ни отмена не обращаются к провайдеру. Подробности и оставшиеся задачи: [backend/billing/README.md](backend/billing/README.md).
