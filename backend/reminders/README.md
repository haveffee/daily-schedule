# Фоновые напоминания HVF

Отдельный бесплатный Cloudflare Worker отправляет Web Push, когда сайт закрыт и компьютер выключен. Основное приложение остаётся на GitHub Pages, синхронизация — в прежнем Firebase. Worker проверяет Firebase ID Token и хранит только снимок дел, повторов, пропусков и подписки устройств. Финансовые данные передавать ему нельзя.

## Развёртывание

Нужен Cloudflare Free аккаунт. Подключать Workers Paid или Firebase Blaze не требуется. Команды выполняются из этой папки, Node.js 24+.

1. Установить зависимости: `pnpm install --frozen-lockfile`. Для установки без выполнения сторонних build scripts можно использовать `pnpm install --ignore-scripts`; опубликованные бинарные зависимости Wrangler уже входят в пакеты. Если pnpm сообщает об игнорированных scripts, Wrangler можно вызывать напрямую: `node node_modules/wrangler/bin/wrangler.js ...`.
2. Войти: `node node_modules/wrangler/bin/wrangler.js login`.
3. Создать базу: `node node_modules/wrangler/bin/wrangler.js d1 create hvf-reminders`.
4. В `wrangler.jsonc` заменить `REPLACE_WITH_D1_DATABASE_ID` на полученный `database_id`. Имя binding оставить `DB`.
5. Создать ключи один раз: `node scripts/generate-vapid.mjs`. Скрипт напечатает публичный ключ и запишет приватный ключ в игнорируемый `.vapid-private-key`. В `wrangler.jsonc` заменить `REPLACE_WITH_GENERATED_PUBLIC_KEY` на публичный ключ. Приватный ключ в исходники, GitHub Pages или переменные JavaScript не помещать.
6. Записать приватный ключ в Worker Secret. PowerShell: `Get-Content -Raw .vapid-private-key | node node_modules/wrangler/bin/wrangler.js secret put VAPID_PRIVATE_KEY`. POSIX shell: `node node_modules/wrangler/bin/wrangler.js secret put VAPID_PRIVATE_KEY < .vapid-private-key`. Сам ключ в терминал не выводить.
7. Применить схему: `node node_modules/wrangler/bin/wrangler.js d1 migrations apply DB --remote`.
8. Проверить сборку: `node node_modules/wrangler/bin/wrangler.js deploy --dry-run`.
9. Опубликовать: `node node_modules/wrangler/bin/wrangler.js deploy`.
10. Проверить `https://<имя-worker>.<аккаунт>.workers.dev/v1/health`: ожидается `{"ok":true,"configured":true}`. Добавить URL Worker в публичную конфигурацию клиентских напоминаний и опубликовать основной сайт.

Cron `* * * * *` уже включён в конфиг. Cloudflare предупреждает, что изменения cron распространяются до 15 минут. Не менять пару VAPID ключей при обычном обновлении: существующие подписки привязаны к публичному ключу. Приватный ключ можно восстановить из сохранённого локального файла, но через API Worker прочитать его нельзя.

## API

Источник браузера разрешён только `https://haveffee.github.io`. Для защищённых маршрутов нужен `Authorization: Bearer <Firebase ID Token>` из проекта `daily-schedule-sync-fc374` и `Content-Type: application/json`. UID берётся только из проверенного токена. Максимальное тело — 128 КиБ, максимум 1000 записей в снимке.

| Маршрут | Запрос | Ответ |
| --- | --- | --- |
| `GET /v1/health` | — | `{ok:true,configured:true}` либо 503 |
| `GET /v1/config` | — | `{publicKey:"..."}` |
| `PUT /v1/plan` | `{records:[...]}` | `{ok:true,records:N,jobs:N}` |
| `POST /v1/devices` | `{subscription:{endpoint,keys:{p256dh,auth}}}` | `{ok:true,deviceId:"..."}` |
| `DELETE /v1/devices` | `{endpoint:"..."}` | `{ok:true}`; повторное удаление допустимо |
| `POST /v1/test` | `{endpoint:"..."}` | `{ok:true,accepted:true}` либо ошибка |

Ошибка имеет вид `{error:"Понятное сообщение",code:"machine_code"}` с HTTP 400/401/403/404/409/410/413/415/429/503. Принятый тест означает подтверждение push-сервиса, а не подтверждение прочтения пользователем. Повторный тест доступен через 30 секунд.

Снимок включает все `routine`, все `routine-skip` и все экземпляры `task` с `routineId`, в том числе завершённые, перенесённые и с выключенным напоминанием. Иначе пропуск или перенос повтора не сможет подавить виртуальное событие. Обычное дело без `routineId` с выключенным напоминанием или уже выполненное можно не передавать: `PUT` полностью заменяет снимок и отменяет его прежнюю неотправленную очередь. Worker оставляет только поля расписания:

- Общее: `id`, `kind`, `title`, `time`, `reminderMinutes`.
- Дело: `date`, `done`, необязательные `routineId`, `occurrenceDate`, `lastMovedAt`, `updatedAt`.
- Повтор: `startDate`, `untilDate`, `weekdays` (1 — понедельник, 7 — воскресенье), `active`.
- Пропуск: `routineId`, `occurrenceDate` (либо `date`).

`reminderMinutes` принимает `null`/`"off"`, 0, 5, 10, 15, 30, 60, 1440. При включённом напоминании требуется точное `time: "ЧЧ:ММ"`. Отсутствующее поле у сохранённого экземпляра повтора наследуется от серии; явный `null` выключает напоминание только этому экземпляру. Все даты и часы трактуются как время Минска UTC+3, независимо от часового пояса устройства.

Клиент должен отправлять снимок только после синхронизации Firebase и после каждого изменения дел. При выходе из Google нужно удалить подписку устройства с токеном прежнего аккаунта, затем отписаться в PushManager. Один endpoint не присваивается другому UID автоматически. Если браузер сохраняет токен прежнего аккаунта, он действителен только до штатного истечения Firebase ID Token.

Push содержит `{title,body,url,date,taskId,tag}`. Service Worker обязан сразу показывать видимое уведомление; скрытые push в Safari запрещены. `date` помогает открыть нужный день. URL всегда ведёт на приложение HVF; данных другого аккаунта в payload нет.

## Очередь и ограничения

Планы хранятся в D1. При изменении снимка неотправленные и уже захваченные задания удаляются; проверка версии плана перед отправкой не позволяет старой фоновой сборке восстановить удалённое дело. Уже начатую сетевую доставку отозвать невозможно. Сохранённые задания со статусом `sent` подавляют повторную отправку того же экземпляра, времени и отступа. История удаляется через 7 дней, когда напоминание уже не может попасть в допустимый интервал доставки.

Горизонт — сегодня и два следующих дня. Cron каждый день достраивает горизонт из сохранённых повторов без участия открытого браузера; это покрывает и напоминания за 24 часа. За минуту обрабатывается до четырёх отправок и один план, которому нужен новый горизонт. Максимум: 20 аккаунтов, 5 устройств на аккаунт, 200 напоминаний на ближайшие три дня (до 1000 заданий устройств). Эти границы рассчитаны на личное приложение, не на публичный сервис.

Если будущие дела позже образовали слишком большой трёхдневный пакет или отдельный план не удалось достроить, очередь остальных аккаунтов продолжает работать. Для проблемного плана D1 сохраняет код ошибки и задержку повторной сборки на час; существующие корректные задания сохраняются до отправки или истечения срока. Новый снимок плана сразу снимает задержку. Ограничение хранится в базе, поэтому новый экземпляр Worker не выбирает один и тот же сломанный план каждую минуту.

Захват задания атомарный, аренда — 2 минуты. Ошибки сети, 429 и 5xx повторяются через минуту, максимум 5 попыток. Напоминания старше 10 минут не отправляются. Ответы 404/410 удаляют устаревшую подписку и её очередь. После сбоя между принятием push-сервисом и записью результата возможна повторная доставка; стабильный `tag` позволяет системе объединять такое уведомление. Web Push не гарантирует доставку ровно в секунду и не заменяет будильник: сеть, настройки уведомлений и «Фокусирование» влияют на отображение.

Сервис работает в бесплатных квотах для личного использования: Workers Free — 100 тысяч запросов/сутки, 10 мс CPU на запрос/cron; D1 — 5 млн прочитанных и 100 тысяч записанных строк/сутки. Снимки вставляются одним JSON1 SQL-запросом, а не отдельным запросом на каждое задание. Отправка на произвольные адреса заблокирована: допустимы HTTPS endpoints Apple, Google FCM, Mozilla и Microsoft WNS; редиректы при отправке запрещены. Полные тела запросов, токены и ключи не логируются, observability выключена.

На iPhone требуется iOS 16.4+, установка сайта на главный экран и явное разрешение по нажатию кнопки внутри установленного приложения. Обычная вкладка Safari на iPhone не является достаточной установкой.

## Проверки

Из корня репозитория: `node --test tests/backend-reminders.test.cjs` после установки зависимостей этой папки. Проверки исполняют production SQL на SQLite: авторизацию/JWT, изоляцию UID, CORS и ограничения JSON, защиту endpoints, переносы/пропуски повторов, скользящий горизонт, атомарный захват, отмену и повторы, 404/410 и реальную сборку зашифрованного push библиотекой.
